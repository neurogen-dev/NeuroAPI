# Как переподключиться после старой неудачной настройки

Эта инструкция для тех, кто уже пытался подключить Codex CLI/Desktop или Claude Code/Desktop к NeuroAPI и видел ошибки, пустой список моделей либо запросы к ChatGPT/Anthropic. Проекты и рабочие файлы удалять не нужно. Ниже отдельно указано, что меняет автоматический установщик и что проверить вручную.

## 1. Сохраните настройки и проверьте ключ

1. Закройте Codex и Claude Code/Desktop. Сохраните копии существующих `~/.codex/config.toml`, `~/.codex/neuroapi-host.config.toml` и `~/.claude/settings.json`, если такие файлы есть (Windows: в `%USERPROFILE%`). Если у вас задан `CODEX_HOME`, используйте его вместо `~/.codex`.
2. В [кабинете NeuroAPI](https://neuroapi.host/login?redirect=/dashboard/tokens) проверьте, что ключ активен, у него разрешены нужные модели и доступен нужный тариф. Обычный ключ подходит всем четырём клиентам: копируйте его целиком, включая `sk-`. Если старый ключ нигде не виден полностью, создайте новый: не пытайтесь восстановить его из снимков экрана или логов. Ротация нужна обязательно, если ключ был опубликован или передан посторонним; из-за одной ошибки соединения менять его не требуется.
3. Проверьте [каталог и цены](https://neuroapi.host/price). Сохранённое название модели из старой сессии не гарантирует доступность на вашем ключе.

**Адреса сейчас:** Codex CLI/Desktop — `https://codex.neuroapi.host/v1`; Claude Code/Desktop — `https://claude.neuroapi.host`; другие OpenAI-совместимые программы — `https://neuroapi.host/v1`. Для Claude не добавляйте `/v1/messages`, для Codex не добавляйте `/responses`: клиент допишет этот путь сам.

## 2. Выберите способ переподключения

### Автоматически (рекомендуется для CLI и Codex Desktop)

1. Скачайте [актуальный ZIP установщика](https://github.com/neurogen-dev/NeuroAPI/archive/refs/heads/agents.zip) и распакуйте в новую папку. Старый скачанный ZIP не обновляется сам.
2. На Windows запустите `setup-windows.bat`; на macOS в этой папке выполните `bash setup-macos.command`.
3. Введите действующий ключ в защищённый запрос. Установщик проверит каталоги моделей без платной генерации. Если нужен **Codex Desktop**, ответьте «да» на отдельный вопрос. Если он сообщает о конфликте `config.toml`, остановитесь и разберите его по разделу ниже; не удаляйте файл целиком.
4. Перезапустите Codex Desktop. Для терминала откройте новое окно и запускайте именно `codex-neuroapi` и `claude-neuroapi` (macOS: при необходимости `~/.local/bin/...`). Обычные `codex` и `claude` могут использовать старую настройку.
5. **Claude Desktop подключается вручную в самом приложении** через Developer Mode → Configure Third-Party Inference по [инструкции](https://neuroapi.host/docs/claude-desktop). Установщик CLI не переносит в него настройки автоматически.

Повторная установка в тот же каталог проверяет ownership управляемых файлов и сохраняет исходную резервную копию Codex Desktop. При конфликте она намеренно отказывается перезаписывать чужие изменения.

### Вручную (если установщик не подходит)

Следуйте [готовым ручным шаблонам](copy-paste-setup.md): там указаны точные пути, временный безопасный ввод ключа, профиль Codex и файл Claude Code для Windows/macOS. Для Codex Desktop там же есть шаблон с защищённым helper после setup; Claude Desktop подключается через штатную форму приложения. Вручную настроенное меню моделей может отличаться от каталога, который получает managed launcher.

## 3. Уберите старый конфликт точечно

| Где была старая попытка | Что проверить после сохранения копии |
|---|---|
| Codex CLI | В `codex-neuroapi` команда `/debug-config` должна показывать профиль `neuroapi-host`, provider `neuroapi` и новый адрес. Старый `[profiles.neuroapi]` в общем `config.toml` не является текущим отдельным profile-файлом. Если задан `CODEX_HOME`, используйте одно и то же значение при установке и запуске. |
| Codex Desktop | В пользовательском `config.toml` должен быть `model_provider = "neuroapi_agents"` и `base_url = "https://codex.neuroapi.host/v1"`. В GUI откройте **новую локальную** задачу: старый разговор или облачная задача могут продолжать идти прежним путём. Присутствие аккаунта ChatGPT в приложении само по себе не доказывает, каким провайдером выполнен новый запрос. |
| Claude Code | Запустите `claude-neuroapi`, затем `/status`: база `https://claude.neuroapi.host`, источник ключа `apiKeyHelper`. Старые `ANTHROPIC_BASE_URL`, `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, Bedrock/Vertex/Foundry overrides и сохранённые параметры пользователя могут менять ручной запуск `claude`; managed launcher создаёт изолированные settings для своей сессии. |
| Claude Desktop | В приложении проверьте выбранный сторонний endpoint и ключ по [инструкции](https://neuroapi.host/docs/claude-desktop), затем начните новый локальный чат. Настройки Claude Code CLI не настраивают Claude Desktop автоматически. |

Если установщик видит чужой `neuroapi-host.config.toml` без ownership marker или старый `[model_providers.neuroapi_agents]` в `config.toml`, он должен остановиться. Сравните файл с резервной копией, удалите **только** старый конфликтующий блок или переименуйте **только** старый профиль, затем повторите setup. Не создавайте marker вручную и не удаляйте весь `~/.codex`: там могут быть ваши другие профили и история. Если uninstaller остановился из-за изменённого `config.toml`, сначала восстановите или вручную перенесите свои изменения, чтобы Codex Desktop не остался без credential helper.

## 4. Докажите, что запрос идёт через NeuroAPI

1. В каждом нужном клиенте выберите модель, видимую вашему ключу. В Codex CLI проверьте `/debug-config`, в Claude Code — `/status`. В Desktop создайте **новую локальную** задачу/чат.
2. Дайте короткую реальную задачу, например создать простой `index.html` в тестовой папке. Проверьте, что файл появился и его содержимое соответствует ответу. Каталог моделей или успешная авторизация сами по себе этого не доказывают.
3. Откройте [историю использования](https://neuroapi.host/dashboard/logs) в кабинете NeuroAPI и найдите запрос в то же время с ожидаемой моделью. Если в истории нет запроса, проверьте локальный профиль, URL и источник ключа. Если запрос есть и завершился ошибкой, смотрите её код и [решение проблем](troubleshooting.md).
4. Если Codex CLI с WebSocket не соединяется, временно установите `supports_websockets = false` в `neuroapi-host.config.toml`, перезапустите launcher и повторите задачу по HTTP/SSE. Это диагностика сети/транспорта; setup вернёт значение `true` при переустановке.

**Не публикуйте ключ, полный конфиг с секретами или сырой дамп запросов** в issue и скриншотах. Для обращения в поддержку достаточно клиента и версии, ОС, времени запроса, модели, кода ошибки, того, был ли запрос в истории NeuroAPI, и обезличенного фрагмента `/debug-config` или `/status`.
